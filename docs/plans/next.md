# 다음에 할 일 (M1 이후)

> 기준: **"매일 켜두고 쓰는 도구"가 되기까지 무엇이 남았는가.**
> 기능 목록 순서가 아니라, 실제 사용을 막고 있는 것 순서로 정렬한다.

## 지금 상태 요약

M1은 관제 루프가 도는 것까지 왔다 (G5 실측 완료, [m1-result.md](m1-result.md)).
하지만 아직 **일과 중에 계속 켜둘 수 있는 상태는 아니다.** 막는 것 셋:

| 막는 것 | 지금 무슨 일이 벌어지나 |
|---|---|
| 터미널 2개를 직접 띄워야 함 | `pnpm host` + `pnpm dev`. 껐다 켜는 비용이 커서 "잠깐 열어보기"가 안 된다 |
| host가 죽으면 세션도 죽음 | 기록은 남지만 대화를 못 이어간다. 새 세션을 만들어야 한다 |
| 자리를 뜨면 승인을 놓침 | 브라우저 탭 뒤에 있으면 알 방법이 없다. 관제탑의 존재 이유가 무력화된다 |

셋 다 M1 범위 밖이었고 의도된 것이지만, **이 셋을 해결하기 전에는 Codex든 깃 패널이든 쓸 일이 없다.**
그래서 다음 마일스톤은 기능 추가가 아니라 **상시 가동**으로 잡는다.

## M1.5 — 상시 가동 (다음 작업, 권장)

목표: **앱 아이콘 하나로 뜨고, 껐다 켜도 이어지고, 자리를 비워도 놓치지 않는다.**

### A. 데스크톱 셸 (Tauri 1~3단계)

[platform-abstraction.md §5](../platform-abstraction.md)의 플레이북을 그대로 따른다.
1~3단계까지만 해도 목표가 달성되고, **UI 코드는 한 줄도 안 바뀐다** (설계의 회수 시점).

- **A-1. `apps/desktop` 생성 + 사이드카 수퍼바이즈** — Tauri가 agent-host를 spawn하고,
  포트·토큰을 stdout에서 읽어 UI에 전달. 크래시 감지 시 재시작.
  완료 기준: 앱 실행 → 터미널 없이 세션 생성·대화 완주.
- **A-2. `createTauriPlatform()` = web 구현 재사용** — 전부 WS 위임이라 신규 코드가 거의 없다.
  완료 기준: 같은 계약 테스트 스위트가 tauri 구현에서도 통과 (지금 web/mock 2개 → 3개).
- **A-3. system 포트를 Tauri 플러그인으로 교체** — 알림·독 뱃지·전역 단축키·IDE로 열기.
  capability가 true로 바뀌며 UI 기능이 저절로 켜진다 (이미 그렇게 설계돼 있음).

### B. 놓치지 않기 (알림)

- **B-1. 승인·오류 발생 시 OS 알림** — 클릭하면 해당 세션으로 점프.
- **B-2. 독 아이콘 뱃지** — 대기 건수. 승인만 셀지 전부 셀지는 써보고 정한다.
- **B-3. "전부 완료" 알림 1회** — 모든 세션이 일을 마쳤을 때 (product-spec에서 결정한 정책).
- **B-4. 전역 단축키** — 앱이 백그라운드일 때도 ⌘⇧A로 대기 세션 호출.

### C. 끊기지 않기 (복원)

- **C-1. 세션 resume (FR-10)** — host 재시작 시 저장된 external_id로 `resume` 시도.
  성공하면 대화를 그대로 이어가고, 실패하면 지금처럼 "기록 보기 + 새 세션"으로 폴백.
  M0에서 SDK resume은 이미 검증됨 (이전 대화 기억 확인).
- **C-2. 승인 규칙 영속 복원** — "항상 허용"이 지금은 세션 메모리에만 있다.
  store의 `approval_rules`와 실제로 연결한다 (테이블은 이미 있음).
- **C-3. 워크스페이스 스냅샷** — 창 레이아웃·포커스 세션·읽음 위치 복원.

### D. 규모 견디기

- **D-1. 대화 가상 스크롤** — 메시지 수백 개 넘어가면 지금 구조는 버겁다.
  `@tanstack/react-virtual`은 이미 설치돼 있고 안 쓰고 있다.
- **D-2. 메시지 윈도잉** — 비포커스 세션 메시지 해제 ([state-management.md §4](../state-management.md) 설계대로).
- **D-3. 성능 실측** — 세션 4개 유휴 상태에서 §7.1 목표 대비 측정 (지금은 host만 쟀다).

## M2 — 관제 완성 (그다음)

상시 가동이 되고 나면 그때 폭을 넓힌다.

- **Codex 어댑터** — M0에서 프로토콜을 이미 다 파악했고 타입 생성기도 확인했다.
  어댑터 하나만 추가하면 UI·core·protocol은 그대로 (C3 설계 검증의 실전 시험).
- **깃 패널** (Changes/History/Branches) + IDE 줄 점프 → 직후 커밋/스테이징 (v1.5 확정분)

- **첨부·이미지 붙여넣기** — 스크린샷 워크플로우
- **커맨드 팔레트 ⌘K + 대화 전문 검색** (SQLite FTS)
- **단축키 설정 화면**

## 짚어둘 결정 사항

1. **Tauri 전환을 M1.5로 당긴 이유** — 원래 로드맵은 M3 근처였지만, 실사용 진입 비용이
   가장 큰 마찰이고 알림·뱃지·전역 단축키가 전부 Tauri에 묶여 있다. 관제탑의 핵심 가치
   ("놓치지 않게")가 웹에서는 구현 불가능하다.
2. **Codex를 M2로 미룬 이유** — 도구가 늘어도 매일 안 켜면 의미가 없다.
   상시 가동이 먼저다. 어댑터 작업 자체는 M0 검증 덕에 위험이 낮다.
3. **남은 열린 질문** — 사용량 비용 추정의 단가 테이블 관리 방식 (M3에서 결정).

## 시작할 때

M1과 같은 방식으로 간다: 페이즈별 태스크에 완료 기준(검증 방법 포함)을 붙이고,
사람 확인은 마지막 한 번. 다만 G5에서 배운 것을 반영해 **완료 기준에 "실사용 순서 재현"을
명시한다** — 포커스 상태, 죽은 세션, 재시작 후 같은 조건에서 테스트가 돌아야 한다.
