## 실측이 잡은 결함 5건

자동 테스트가 전부 통과하는 상태에서도 아래는 **실제로 돌려봐야만** 드러났다.

1. **고아 사이드카** — `pnpm` 래퍼로 spawn하면 래퍼만 죽고 손자(node)가 남아 포트를 물었다.
   실제로 3개가 떠 있었다. → tsx 직접 실행 + 프로세스 그룹 종료 + stdin EOF 자가 종료.
   SIGKILL(크래시와 동일)로 실측해 좀비 0 확인.
2. **재기동 후 재연결 실패** — 사이드카를 되살려도 포트·토큰이 바뀌어 UI가 '연결 끊김'에 머물렀다.
   자동 재기동이 무의미했다. → `updateEndpoint` + host-status 구독.
3. **인자 전달 누락** — 수정 중 `.args()`를 지워 host가 즉시 죽었다. 앱은 빈 화면이 됐다.
   컴파일 경고(`unused variable: args`)가 신호였는데 흘려봤다.
4. **stdin EOF 오탐** — TTY 여부로 부모 감시를 켜니, stdin이 `/dev/null`인 스크립트 실행에서
   host가 즉시 자살했다. → `--watch-parent` 명시 플래그.
5. **재개 식별자 저장 시점** — SDK는 세션 id를 첫 init 이벤트에서 준다. 생성 응답에는 없다.
   첫 턴 전에 host가 죽으면 재개 불가 — 기대를 실제 동작에 맞추고 생성 직후에도 저장하도록 했다.

## 구현 중 내린 결정

1. **매처 계산은 core, 전달은 UI** — agent-host는 core를 import하지 않는다는 경계 규칙을 지키기 위해,
   '항상 허용'의 패턴은 UI가 계산해 RPC로 실어 보낸다.
2. **디렉토리 피커는 SystemPort로** — ui가 `@cc/platform/tauri`를 직접 import하면 경계 위반이다.
   데스크톱은 네이티브 피커, 웹 dev는 경로 입력으로 폴백한다.
3. **부모 감시는 명시 플래그** — 자동 감지(TTY)는 오탐이 났다. 수퍼바이저만 켠다.
4. **알림은 개별과 전체 중 하나만** — 같은 순간에 두 번 울리지 않는다.
