# 테마 — 겉모습을 고르는 법, 테마를 쓰는 법

화면의 색, 그림자, 스크롤바는 토큰(`packages/ui/src/styles/index.css`)에서 온다. **테마**는 그
토큰들의 값 묶음이다. 설정 → 모양새에서 어떤 테마를 보일지 고르고, **사용자 테마**는 사람이든
편집기든 에이전트든 누구나 쓸 수 있는 JSON 파일이다(#312).

## 고르기

다른 화면 설정(`UiPreferences`)과 함께 저장되는 설정 넷:

| 설정 | 값 | 하는 일 |
|---|---|---|
| `themeMode` | `dark` · `light` · `system` | 어느 쪽을 보일지. `system`은 OS를 따른다(`prefers-color-scheme`). |
| `themeDark` | 프리셋 id 또는 테마 파일 id | 어두운 쪽의 테마 |
| `themeLight` | 프리셋 id 또는 테마 파일 id | 밝은 쪽의 테마 |
| `accent` | CSS 색, 또는 `null`(기본) | 포커스, 선택, 작업 중 궤도, 체크된 상자를 칠한다 |

두 쪽을 따로 고르는 이유는, OS를 따를 때 사람이 고른 두 테마 사이를 오가게 하기 위해서다. 아무것도
가리키지 않는 id(지운 파일)는 그쪽의 프리셋으로 돌아간다.

**프리셋**은 스타일시트에 있다. `@theme`의 값이 Dark 프리셋이고, 나머지는 모든 색 토큰을 정하는
`[data-theme='…']` 블록이다:

| 프리셋 | id | 쪽 |
|---|---|---|
| Dark | `dark` | 어두운 쪽 (기본) |
| Light | `light` | 밝은 쪽 (기본) |
| High contrast dark | `hc-dark` | 어두운 쪽 |
| High contrast light | `hc-light` | 밝은 쪽 |

Light는 어두운 쪽의 규칙을 뒤집어도 살아남는 형태로 지킨다. 순수한 검정은 당신을 기다리는 것에만
쓰고, 떠 있는 면은 흰색 쪽으로 가며, 대화는 거의 흰 면 위에 카드가 흰색으로 놓인다. 고대비 프리셋은
글을 읽는 모든 면에 대해 모든 잉크를 4.5:1 이상, 가는 선을 3:1 이상으로 둔다. 테스트가 모든 프리셋의
긴급함 순서(아래)를, 고대비 프리셋은 그 두 기준까지 확인한다.

토큰이 아니라 쪽을 따라 바뀌는 것도 몇 있다. `color-scheme`이 따라가고, 응답이 끝났음을 알리는
바람은 밝은 쪽에서 screen 대신 multiply로 섞인다(screen은 흰색을 더 밝게 할 수 없다). 파일 종류
아이콘은 거기서 가는 윤곽선을 얻는다. vscode-icons 몇 개는 어두운 편집기를 위해 옅게 그려져 있기
때문이다.

**강조색은 신호를 칠하지 않는다.** `ink-signal`은 "당신을 기다리는 것"을 위해 남겨 둔 색이다
(product-spec FR-12). 거기에 강조색이 들어가면 평범한 컨트롤이 꼭 눈에 띄어야 할 단 하나와 겨룬다.

## 테마 파일

사용자 테마 하나가 파일 하나다: `<data>/themes/<id>.json`. `<data>`는 `~/.centralu`(개발 빌드는
`~/.centralu-dev`, 테스트는 `CC_DATA_DIR`). id는 파일 이름이고, 소문자, 숫자, 하이픈으로 된다.

```json
{
  "$schema": "./theme.schema.json",
  "name": "Paper",
  "base": "light",
  "tokens": {
    "surface-floor": "#fafafa",
    "ink": "#1a1a1a",
    "ink-faint": "oklch(0.6 0 0)",
    "shadow-modal": "0 24px 60px -12px rgb(0 0 0 / 0.25)"
  }
}
```

- `name` — 설정에 보이는 이름. `base` — `dark` 또는 `light`: 테마가 어느 쪽 것인지, 그리고 파일이
  빠뜨린 토큰을 누구의 값으로 채울지. **일부만 쓴 파일이 보통이다**: 바꾸고 싶은 것만 쓰면 된다.
- `tokens` — 키는 `--color-` 접두사를 뺀 토큰 이름이다(`surface-floor`, `ink-muted`,
  `term-red`). 그림자와 스크롤바 크기는 자기 접두사를 그대로 둔다(`shadow-modal`,
  `scrollbar-size`). 값은 그 종류의 토큰에 브라우저가 받아들이는 어떤 CSS든 된다 — 색(`#rrggbb`,
  `rgb()`, `oklch()`, `color-mix()`, 알파 포함), box-shadow, 길이.
- **스키마.** 호스트가 테마 옆에 `theme.schema.json`을 쓰고, 앱이 만드는 모든 파일은 `$schema`로
  그것을 가리킨다. 그래서 편집기가 토큰 이름을 완성해 주고 오타를 짚어 준다. 같은 스키마가 저장소의
  [`theme.schema.json`](theme.schema.json)에도 있고, 설명이 붙은 전체 토큰 목록은 거기 있다.
- **실수가 앱을 멈추지 않는다.** 모르는 키나 토큰, 브라우저가 거절하는 값은 설정에서 테마 옆에
  적히고 건너뛴다. 읽히지 않는 파일(편집 도중)은 깨진 것으로 적히고, 화면은 마지막으로 읽혔던 판을
  계속 보인다.

**실시간.** 호스트가 폴더를 지켜보고(`packages/agent-host/src/themes.ts`) 바뀔 때마다 알린다
(`themes_changed`). 화면은 목록을 다시 읽고 다시 적용한다. 편집기에서 파일을 저장하면 열린 창이
바뀐다.

**설정에서.** *Customise…*는 지금 보이는 테마를 새 파일로 복사하고(모든 토큰을 적어서) 그것을
고른다. *Edit*은 색 고르개와 텍스트 칸으로 토큰을 바꾼다(알파나 `color-mix()`처럼 고르개가 담지
못하는 값을 위해 텍스트 칸이 있다). *Open file*은 편집기로 열고, *Show in Finder*는 파일을 보여
준다(테마가 이미 파일이니 그것이 내보내기다). *Import…*는 파일을 들여오고, *Delete*는 휴지통으로
옮긴다. 모든 쓰기는 원자적이라(임시 파일 후 이름 바꾸기), 폴더를 읽는 감시자나 에이전트가 반쯤 쓴
파일을 보는 일이 없다.

## 긴급함의 순서

어두운 쪽에서는 밝기가 긴급함이다. 밝은 쪽에서도 성립하도록 말하면, **대비가 긴급함이다**. 글을 읽는
모든 면(바닥, 사이드바, 떠 있는 면, 대화와 그 카드) 위에서 잉크는 이 순서로 도드라져야 한다:

`ink-signal` > `ink` > `ink-muted` > `ink-faint`

설정은 사용자 테마마다 이것을 확인하고(WCAG 대비, 반투명 잉크는 내려앉은 자리에서 잰다), 순서가
깨지면 테마 옆에 경고한다. 거절이 아니라 경고다. 테마는 사람의 것이지만, 순서를 깬 테마는 그 사람을
기다리는 것을 조용히 묻어 버린다.

## 적용되는 방식

`packages/ui/src/app/theme.ts`. `<html>`에: `data-theme`(프리셋), `data-theme-base`
(`color-scheme`이 따른다), 사용자 토큰은 인라인 사용자 속성으로, 그 위에 강조색의 토큰. 토큰을 읽는
모든 것이 따라온다 — 유틸리티(그냥 `@theme`이라 `var()`를 읽는다), CSS, 그리고 전환할 때마다 자기
테마를 다시 읽는 xterm(`components/terminalTheme.ts`).

정해진 선택은 `localStorage`에 담아 두었다가 첫 프레임 전에 `main.tsx`에서 적용한다. 설정은 한 번
왕복한 뒤에야 오기 때문이다. 이것이 없으면 밝은 테마가 어두운 번쩍임으로 열린다. 데스크톱 창에도
어느 쪽인지 알린다(`SystemPort.setWindowAppearance`). 한쪽 모양새로 붙잡힌 창은 페이지에 그
모양새를 보고하므로, System 모드는 창을 OS에 돌려준다. `tauri.conf.json`은 더 이상 창을 Dark로
강제하지 않는다.

**첫 페인트는 그 모든 것보다 먼저다** ([#340](https://github.com/ijun17/centralu/issues/340)). 창을 더 이상 Dark로
강제하지 않자, WKWebView는 번들이 로드될 때까지 자기 기본값을 칠했고, 밝은 OS 모양새에서 그 기본값은 흰색이다.
`main.tsx`는 번들 뒤에야 돌기 때문에, `index.html`(데스크톱과 웹, 같은 텍스트)의 작은 인라인 스크립트가 어떤
스타일시트나 모듈보다 먼저 돈다. 같은 `cc-theme` 캐시를 읽고, 같은 방식으로 쪽을 고르고, `<html>`의
`background-color`와 `color-scheme`을 그 테마의 바닥(사용자 테마 자신의 바닥 토큰, 없으면 프리셋의 것)으로 둔다.
캐시가 없으면 스타일시트의 Dark, `#141414`를 칠한다. `applyTheme`이 두 인라인 값을 지운다. 그때부터는
스타일시트가 맡고, 남은 인라인 `color-scheme`은 전환 뒤에 `html[data-theme-base]`를 이기기 때문이다.

| 결정 | 이유 |
|---|---|
| 인라인 `<style>`이 아니라 스크립트 | 바닥은 캐시에 달려 있고, 캐시는 스크립트만 읽을 수 있다. 값은 CSP가 다루지 않는 CSSOM으로 들어가므로 `style-src`는 그대로다 |
| 데스크톱 CSP는 해시로 허용한다 (`script-src 'self' 'sha256-…'`) | `script-src 'self'`는 인라인 스크립트를 거부한다. 해시는 정확히 이 텍스트만 허용한다. 스크립트가 바뀌면 `tooling/first-paint.test.ts`가 새 해시와 함께 실패한다 |
| 프리셋 바닥은 스크립트에 적어 둔다 | 스타일시트가 아직 없어서 읽어 올 곳이 없다. 같은 테스트가 `index.css`와 대조한다 |
| 네이티브 창은 시작할 때 캐시를 읽지 않는다 | Rust에 페이지가 써 주는 별도 캐시가 필요하다. 문서는 번들에 내장된 자산에서 로드되고 스크립트는 첫 프레임과 함께 칠한다. 남는 것은 그 프레임 전의 틈뿐이고, 두 번째 캐시를 둘 만하지 않다 |
