## 무엇인가

에이전트 코딩 도구를 실전에서 쓰면 자연스럽게 여러 프로젝트 × 여러 세션을 동시에 굴리게
된다. 그때 생기는 문제는 "전부를 동시에 못 본다"가 아니다. **터미널 탭이 흩어지고, 그중
무엇이 내 입력에 막혀 있는지 알 수 없다**는 것이다. 무엇이 바뀌었는지 보려고 프로젝트마다
IDE를 띄우면 램과 배터리가 작업값을 넘어선다.

Centralu는 그것을 위한 관제탑이다. 코드를 쓰지 않는다. 에이전트들이 무엇을 하고 있는지
보여주고, **지금 나를 필요로 하는 것**을 골라준다.

두 종류의 기다림을 절대 같은 뱃지로 묶지 않는다. 비용이 다르기 때문이다.
**승인 대기**는 에이전트가 막혀서 아무것도 못 하고 있다는 뜻이고, **응답 대기**는 턴이
끝났다는 뜻이라 오후 내내 그대로 둬도 된다. 이 둘을 합치면 전부를 확인하면서 아무것도
믿지 못하게 된다.

이 앱이 서 있는 원칙은 **막지 말고 보이게 하라**다. 사용자에게서도 에이전트에게서도
선택지를 빼앗지 않고, 워크플로를 강제하지 않는다. 지금 무슨 일이 일어나는지와 무엇이 내
판단을 기다리는지를 보여줄 뿐이다. 여기서 가장 비싼 자원은 토큰이 아니라 사람의 주의다.

## 쓰려면 필요한 것

Centralu는 에이전트를 직접 돌리지 않는다. 이미 깔려 있는 CLI를 구동한다. 아래가 없으면
앱은 뜨지만 세션을 만들 수 없다.

| | |
|---|---|
| **Node 22 이상** | host(사이드카)가 그 위에서 돈다. 없거나 낮으면 기동 시점에 무엇이 필요한지 버전과 함께 말해준다 |
| **`claude` CLI** + 로그인 | Claude Code 세션용 — `npm i -g @anthropic-ai/claude-code` |
| **`codex` CLI** + 로그인 | Codex 세션용 — `npm i -g @openai/codex`. 안 쓸 거면 없어도 된다 |

둘 중 하나만 준비돼 있어도 시작할 수 있다. 첫 실행 화면이 둘 다 검사해서 무엇이 있는지
보여주고, 없는 것은 설치·로그인 명령까지 함께 적는다.

## 설치

```bash
npm i -g centralu   # 베타 — centralu@beta 로 베타 줄에 고정할 수도 있다
centralu            # 실행
centralu install    # /Applications에 넣기 (Spotlight·Launchpad에 뜨게)
centralu update     # 새 버전이 있으면
```

`centralu install`이 별도 명령인 것은 의도다. 묻지도 않고 postinstall로 남의
`/Applications`에 쓰는 짓은 하지 않는다. `centralu uninstall`이 그것을 되돌리며,
대화 기록은 건드리지 않는다.

> **왜 다운로드가 아니라 npm인가.** macOS는 앱을 열어보고 위험하다고 판정하지 않는다.
> `com.apple.quarantine` 딱지가 붙어 있는지를 볼 뿐이고, 그 딱지는 **파일을 받아온
> 프로그램이** 붙인다 — 브라우저는 붙이고 npm은 안 붙인다. 똑같은 빌드인데 다운로드로
> 받으면 "악성 코드가 없음을 확인할 수 없습니다"가 뜨고, npm으로 설치하면 그냥 열린다.
> 추정이 아니라 실측이다. 값과 방법은
> [배포 점검표 §2](docs/plans/beta-release-checklist.md)에 있다.

## 어디서 도는가

| | |
|---|---|
| **macOS, Apple Silicon** | npm에 올라가 있고, 이 프로젝트가 매일 개발되는 환경이다 |
| **Linux, x86-64** | CI에서 빌드된다. 발행 안 됐고, **아직 아무도 실행해본 적이 없다** |
| **Windows · Linux arm64 · 인텔 맥** | 빌드 자체가 안 된다 ([#14](https://github.com/ijun17/centralu/issues/14), [#29](https://github.com/ijun17/centralu/issues/29)) |

Linux 줄은 설명이 더 필요하다. 이 프로젝트에 리눅스 기계를 가진 사람이 없어서, CI는
편의가 아니라 **리눅스 번들이 존재해본 유일한 장소**다. 푸시마다 실제로 빌드된다:
[run 32289487033](https://github.com/ijun17/centralu/actions/runs/32289487033)에서
78 MB AppImage와 5.1 MB `.deb`가 나왔고 둘 다 아티팩트로 내려받을 수 있다.

일어나지 않은 것은 **아무도 그것을 켜보지 않았다**는 사실이다. 컴파일된다는 것과 돈다는
것은 다른 주장이고, 지금 증명된 것은 앞의 것뿐이다. 그래서 `centralu-linux-x64`는 npm
레지스트리에 없다 — 플랫폼을 안 올려두면 npm이 "아직 지원하지 않습니다"라고 정직하게
답하고, 그편이 열릴지 모르는 것을 설치시키는 것보다 낫다. 지금은 CI 아티팩트가 유일한
경로이며, GitHub 아티팩트는 zip이라 압축을 푼 뒤 AppImage에 `chmod +x`를 해야 한다.

리눅스를 쓰고 첫 번째가 될 의향이 있다면
[#14](https://github.com/ijun17/centralu/issues/14)에 결과를 적어달라. 아무 일도 안
일어났다는 것도 결과다.
