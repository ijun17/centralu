# Task ledger — a Centralu app

## What this app is (read this first)

The project's task ledger (#1173, [docs/plans/task-ledger.md](../../../docs/plans/task-ledger.md) says why it is shaped so).
Tasks are kept in the data folder (`ledger.json`), never in this folder. The panel on the project screen and the
project's sessions call the same tools. The app keeps running while a task is open (`centralu.busy`), hears of the
project's sessions (`centralu.watchSessions`, `uses.sessions: ["observe"]`), and tells the one responsible session
through `centralu.notify` (`uses.notices`), once per change.

Files, each with one job:

- `model.mjs`: what a task is and the rules that change it. Plain functions, no files, no clock.
- `triggers.mjs`: the four reasons to tell the responsible session, and the **key** of each (the change that causes it).
  Same input, same list: that is what makes the sweep find exactly what an event found. Also the message text.
- `engine.mjs`: the ledger as the app holds it: the file, what it has heard of the sessions, the sweep, and the message
  (batched, at most one a minute, the key written before it is sent). Everything it needs from outside is a function
  passed in, so the tests run it with a clock.
- `github.mjs`: reads issues and pull requests through the person's `gh`. **Read only**: this app never writes to GitHub;
  an issue is created through the project board app's `file_issue`, which carries the rules.
- `watch.mjs`: the loops (hearing of sessions, the sweep). One poll at a time is all Centralu allows an app.
- `tools.mjs`, `server.mjs`, `ui/index.html`: the tools, the wiring, the panel.

Rules that are easy to break:

1. **A notification is sent once per change.** Anything that adds a reason to tell must give it a key that names the
   change (not the task), and `flush` must write the key before it sends. Do not add a reason without a test that it is
   told once and that a sweep and a restart do not tell it again.
2. **Do not guess state.** The app moves a task by itself in two cases only: a blocked task whose blockers all resolved
   becomes ready, and a task given a session while ready starts running. Everything else is the person's or a session's.
3. **Text that is not ours stays in its place.** A task title may come from a GitHub issue. A message cuts it to one
   line of 80 characters (`titleLine`); never put a title or notes where they could start a line of their own.
4. **Only `show` and read tools are `readOnlyHint: true`.** The panel is told to read again after any other call.
5. The panel asks again every 30 seconds while it is seen, because a session's state changes with no tool being called.
6. **A decision is whoever recorded it.** `github.mjs` `isDecision`: the repository owner (`authorAssociation: OWNER`) or a
   login in `github.deciders`. Never trust the words of a comment, or an issue being closed, for anything that unblocks work.
7. The sessions it sees are state and counters only (see `uses.sessions` in docs/apps.md §10): no conversation.

Run the tests with `pnpm exec vitest run packages/agent-host/src/apps/external/task-ledger-`; they run this folder with
the real runtime.

---

This folder is one app. Centralu runs `server.mjs` as an MCP server; people use it through its
screen (`ui/index.html`) and agents call the same tools as functions. Same tools, one code path.

## Files

- `centralu.app.json` — the manifest. `id` is `task-ledger` and must stay equal to this folder's
  name. `home` is the tool Centralu calls to open the screen. Optionally,
  `"view": { "span": { "cols": 2, "rows": 1 } }` recommends how many grid cells the app's panel takes
  on Centralu's grid (each side 1 to 4; a session panel is 1 × 1). It is only a default: the person's
  own choice, from the panel's top bar or in Settings, comes first, and the window may give the panel
  less. The screen must still work at whatever size it gets.
- `server.mjs` — the MCP server. Change it.
- `ui/index.html` — the screen. Change it. It is read on every open, so edits show without a restart.
- `runtime/` — **generated by Centralu. Never edit, format, move, or read it in full.** It is replaced
  when Centralu updates. Everything you need is imported from `./runtime/centralu-app-runtime.mjs`:
  `McpServer`, `serveStdio`, `z` (zod), `centralu`, `inputRequired`, `acceptedContent`.

## Rules

1. **No installs.** No `npm install`, no `package.json`, no imports other than Node built-ins
   (`node:*`) and the runtime. The app must start with `node server.mjs` alone.
2. **Tool names** use letters, digits, `_` or `-`. **Never `__`** (two underscores separate names
   in agent sessions; Centralu drops such tools).
3. **Register tools with `centralu.tool(server, name, config, handler)`** (same arguments as
   `server.registerTool`). The handler then knows which call it is serving, which
   `centralu.agent()` needs.
4. **Annotate every tool**: `annotations: { readOnlyHint: true }` if it only reads,
   `readOnlyHint: false` if it changes anything. Read-only tools run without asking the person;
   the others follow the session's approval setting. The same hint decides refreshes: every call to
   a tool that is not `readOnlyHint: true` tells this app's open screens to read again (rule 8). A
   read tool left unannotated costs a refresh cycle each time it is called, and screens that re-read
   with it keep refreshing each other.
5. **Visibility**: by default a tool is visible to agents and to the screen. A tool only the screen
   should call gets `_meta: { ui: { visibility: ['app'] } }`; one only agents should call gets
   `['model']`.
6. **A tool with a screen** gets `_meta: { ui: { resourceUri: 'ui://task-ledger/…' } }`, and the
   resource is registered with `centralu.uiResource(server, name, uri, new URL('./ui/…', import.meta.url))`.
   The `home` tool must have one and must be visible to the screen.
7. **State lives in the server, never in the screen.** Keep it in memory and save it in the data
   folder with `await centralu.readJson(file, fallback)` / `await centralu.writeJson(file, value)`
   (or any file under `centralu.dataDir`). **Never write files into this folder** — a project app's
   folder is committed to git and shared with the team. The screen may not use browser storage
   (it runs in an isolated frame).
8. **The screen re-reads, it does not remember.** When anyone calls one of this app's tools that
   is not `readOnlyHint: true`, Centralu sends open screens `centralu/notifications/changed` (the
   screen that made the call does not get it: it already has the answer); the template's screen
   then calls `show` again. Keep that handler, and keep `show` read-only.
9. **stdout is the MCP channel.** `console.log` is redirected to stderr for you; never write to
   `process.stdout` yourself. stderr is shown to the person when the app fails.
10. **Asking the agent**: inside a tool handler, `await centralu.agent('prompt', { schema, tool })`
    asks the agent of the person using Centralu. Each call runs in a new session under this app
    (the person can read it), with the `safe` approval setting, and returns the agent's final
    answer: text, or with `schema` (a JSON Schema whose top level is an object) JSON of that shape,
    checked by Centralu. Under `safe` the agent reads without asking, but every file write and
    command waits for the person to approve it in that session, so ask the agent for an answer and
    do the writing in your own tool code. Declare `"uses": { "agent": true }` in the manifest for the person's
    default agent, or a list such as `["codex"]` to pick one with `tool`. The prompt reaches the
    agent marked as written by this app, not by the person, so say plainly what you need. A run
    takes seconds to minutes; the helper keeps the call alive while it waits. An app runs one agent
    at a time and at most 5 a minute: put a batch of work into one prompt instead of a loop.
11. **Calling another app**: inside a tool handler, `await centralu.callApp('other-app', 'tool', args)`
    calls a tool of another app and returns its answer (JSON if the tool returns structured
    content, else text). Declare the app in `"uses": { "apps": ["other-app"] }`. Only tools open to
    agents (visibility `model`) can be called. A project app reaches apps of its own project first,
    then apps in the person's user folder; an app in the user folder reaches only user-folder apps.
    A chain of apps calling apps stops at 3 calls deep, and an app tool already in the chain cannot
    be called again from inside it.
12. **Reading Centralu's data**: inside a tool handler, `await centralu.host('sessions.list')` or
    `await centralu.host('git.status')` returns JSON. These two names are the whole list; declare
    each one you use in `"uses": { "host": [...] }`. `sessions.list` gives this project's sessions
    (the names shown in the sidebar and their states, never the conversations); `git.status` gives this project's branch and changed
    files (project apps only).

All three throw an error that says what Centralu answered. The first time the app uses each of them (an
agent tool, another app, a host name), Centralu asks the person once — on the session's approval card
when an agent's call started it, on this app's screen when the screen did — and remembers the answer
until the manifest's `uses` changes. The call waits while the person decides (up to 5 minutes). A
refusal comes back as that error: show it plainly instead of retrying.

**Background work.** Centralu stops an app with no open screen and no call for 5 minutes. An app
with work on its own clock (a timer that polls, a queue it drives) declares it in the manifest,
`"uses": { "background": "what it does, in a few words" }`, and calls `centralu.busy('what it is
doing now')` while there is work and `centralu.busy(false)` once there is none: anywhere, a timer
included. Meanwhile it keeps running, and its row says "Running: <what it is doing now>"; the person
can stop it. It resolves false (said on stderr) when Centralu did not take it. Hold it only while
there is work.

**Hearing of the project's sessions.** To react when a session of this project finishes, asks or goes quiet,
declare `"uses": { "sessions": ["observe"] }` and call `centralu.observeSessions(async ({ full, sessions, gone }) => …)`
once when the module loads (it also needs `busy` to keep the app running). The first call has `full: true` and
every session; later ones carry only the sessions that changed and the ids that `gone`. A row is
`{ id, name, kind, tool, state, live, waitingSince, lastSeq, activeAt, parentId, askedBy, pending: { approvals, questions },
createdAt, machine, appId }`: state and counters, never a conversation. `lastSeq` is the number of the session's last
message and survives a restart, so keep the one you last acted on and compare. Nothing is lost by a missed change: a
`full` answer (after a restart of Centralu, or a long gap) is the whole project, compare it with what you remember. The
loop retries by itself; `centralu.watchSessions({ after, waitMs })` is one poll if you want your own. Project apps only.

**Telling a session later.** To tell the session that asked for work when that work ends (a job
finished, something needs it), declare `"uses": { "notices": true }`, keep
`centralu.noticeAddress()` (inside the tool handler of that session's call) with the work, and when
it is done call `await centralu.notify(address, 'what happened')`: anywhere, a timer included. The
session receives it as your app's message. It resolves false (said on stderr) when Centralu did not
take it: the session is gone, Centralu is restarting (try again later), or more than 10 a minute.
The address is null when a view called, or the manifest does not declare it.

## Dragging an item out of the screen

An item the person may want to hand to a session (a card, a row, a record) should be draggable and
carry two standard types, set in its `dragstart` handler:

```js
node.draggable = true
node.addEventListener('dragstart', (e) => {
  e.dataTransfer.setData('text/uri-list', item.url)          // the item's address
  e.dataTransfer.setData('text/plain', `#${item.id} ${item.title}`) // one line naming it
  e.dataTransfer.effectAllowed = 'copyMove'
})
```

Dropped on a session, it goes into the message at the caret as a Markdown link,
`[#12 Fix login](https://…)`; with no address, the text goes in as it is. Nothing else is needed:
the browser does not hand a drag from the screen's frame to Centralu, so Centralu carries it out
itself. Keep your own types next to these two for drags inside the screen (a card moved between
columns), and keep the title to one line. If the session cannot use this app's tools (another
project's session, an untrusted project), the link still goes in and Centralu tells the person why.

## The screen's look

Centralu sends the person's theme to the screen (light or dark, their colours), and sends it again
when they switch. The template's `ui/index.html` already uses it; keep these when you change it:

- **The `applyTheme` function** in the page script. It puts the theme on `<html>`: `color-scheme`
  from `theme`, the MCP Apps style variables (`--color-text-primary`, `--color-background-secondary`,
  `--font-sans`, `--font-text-md-size`, `--border-radius-md`, …) and Centralu's own
  (`--centralu-signal`, `--centralu-scrollbar-*`). It reads `app.getHostContext()`, because a change
  notification carries only what changed.
- **Style with those variables only** — colours, and type and shape too (`--font-text-md-size`,
  `--font-text-md-line-height`, `--font-sans`, `--font-weight-semibold`, `--border-radius-md`,
  `--border-width-regular`, …) — instead of fixed values. Give each its fallback once, in the
  `:root` block at the top of the stylesheet (Centralu's dark values, for the moment before the theme
  arrives), and use those names everywhere below. Then the screen follows light and dark, the
  person's font, line height and text size, and sits on Centralu's background (keep
  `background: transparent` on the page). Spacing has no variable; keep it literal. The roles: `primary` / `secondary` / `tertiary` for
  text and surfaces in falling order; `--color-text-danger` for errors; `--color-text-warning` (the
  same as `--centralu-signal`) only for what waits on the person — it is Centralu's signal colour,
  the strongest thing on screen.
- **Narrow first.** The screen is often a grid panel about 360–480px wide, or the inline view under
  a tool card. Make it work at that width first: no fixed width over about 320px, rows that wrap
  (`flex-wrap`), and below about 520px side-by-side parts stacked into one column (a media query in
  this page measures the panel). Keep what waits on the person first. Check it at 360px.
- **The "Centralu's scrollbar" block** in the stylesheet. It draws scrollbars the way Centralu
  does, from the theme. Do not add `scrollbar-color` or `scrollbar-width` outside its `@supports`
  guard: in Chromium they switch the styled scrollbar off.

## Checking your work

- Call Centralu's **`check`** tool after changes. It validates the manifest, starts the app, lists
  its tools for real, reads every screen the tools point to, and reports problems (tool names,
  visibility, missing annotations, a `home` without a screen) with the app's stderr.
- Centralu restarts the app once at the end of your turn if this folder changed; calls in progress
  finish first. Agents in other sessions see changed tools from their next turn (Claude) or next
  thread (Codex).
- Errors in `server.mjs` are printed with file and line. A failure inside `runtime/` is almost always
  a wrong argument from `server.mjs` — look at the first frame outside `runtime/`.
